# BrewAssistant 2026.10.0b9 – BOIL med enbart intern vörttemperatur

**Kanal:** HACS beta / GitHub Pre-release · endast övervakat vattenprov
**Manifest:** `2026.10.0b9`
**Tagg efter godkänd beta-merge:** `v2026.10.0b9`
**SOP:** dev → beta → main. `main` uppdateras inte.

## Förändringar sedan 2026.10.0b8

- **BOIL:** BA använder uteslutande BrewZillas interna vörttemperatur,
  `sensor.brewzilla_temperature`, som processtemperatur när **aktuellt**
  brygg-/RAPT-profilsteg är BOIL. Explicit vald BLE-, Control Device- eller
  annan extern mäsktermometer får inte överstyra den regeln.
- Gäller temperaturresolvern, Equipment Learning och Brewfather-rampvillkor.
  Ett aktuellt RCL-steg BOIL kan utlösa regeln även innan BA:s normaliserade
  stegsensor hunnit ikapp. *Nästa* steg BOIL eller *Pre-Boil* ska inte göra det.
- Saknas intern vörttemperatur rapporteras **okänt/otillgängligt**, inte
  BLE-fallback. BA stoppar nya vanliga styrskrivningar (fail-passive) och
  tolkar inte sensorbortfall som STOP. RAPT/BrewZilla behåller ägarskapet,
  målet och pågående profil; inga automatiska heater OFF, pump OFF eller
  utilization 0 p.g.a. bortfallet.
- Tidigare b8-funktioner för reconnect, kvittens, READ-ONLY, RAPT-profilsteg,
  röda overifierade värden och `profile_observed_at` behålls.

## OBS! BZ växlar INTE själv bort från BLE när BOIL börjar

**Operatören måste manuellt växla BrewZillas egen reglergivare till den
interna sensorn inför BOIL.** Använd ett manuellt, fysiskt/verifierat
kontrollsteg och kontrollera att BrewZillas *faktiska reglerkälla* är intern.
Det här är **inte** ett sensorbyte som BA kan utföra i denna release.

B9 säkerställer bara hur **BrewAssistant** väljer sitt temperaturunderlag.
Det finns ingen verifierad RCL-tjänst för att byta BrewZillas fysiska
reglergivare. Inga direkta BA→BZ-kommandon har införts. Spåra den fysiska
frågan i [RCL issue #7](https://github.com/Jocke1970/home-assistant-rapt-cloud-link/issues/7).

## Installation och test

1. Håll RAPT Cloud Link **2026.10.0b4** installerad med prereleases aktiverade.
2. Installera BrewAssistant **2026.10.0b9** från HACS beta och starta om HA.
3. Under övervakat vattenprov: låt Mash/Mash Out använda extern mäskgivare,
   kontrollera att en kommande BOIL inte växlar sensor i förtid.
4. Inför BOIL: växla **manuellt BrewZillas egen reglergivare till intern** och
   verifiera på bryggaren att bytet verkligen skett. Detta sker alltså
   separat från BA:s interna temperaturlogik.
5. När RAPT-profilsensorn faktiskt visar BOIL ska BA använda
   `sensor.brewzilla_temperature`. Kontrollera
   `sensor.brewassistant_brewzilla_mash_temperature_source_entity` och
   motsvarande Equipment Learning-källfält. BLE får fortfarande visa
   diagnostikvärde men aldrig styra BA:s BOIL-logik.
6. Testa separat att saknad intern vörttemperatur inte leder till BLE-fallback
   eller automatiska STOP/0/OFF-kommandon från BA.

## Releasetest och säkerhet

Candidate kräver Python 3.11–3.13, kvalitet, HACS, Hassfest och det
isolerade Home Assistant/RCL-smoketestet på RCL b4. Samtliga kontroller
måste gå grönt **på exakt beta-merge-SHA** innan en ny, unik
`v2026.10.0b9`-tagg och GitHub Pre-release publiceras.
Fysiska STOP/ABORT/readback och verkligt BOIL-provbeteende återstår som
fältgrind inför eventuell stable/main-promotion.
