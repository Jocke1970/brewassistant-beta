# BrewAssistant 2026.10.0b6 — Safety & Premium Brewday Control

**Releasetype:** Pre-release (testbeta, endast vattenprov under fysisk uppsikt)
**Tagg när `dev → beta` är klar:** `v2026.10.0b6`
**Manifest:** `2026.10.0b6`
**Stabil `main`:** lämnas oförändrad

## Nyheter

- Ny premium START-status med **gult pulserande** vid saknade villkor, **grönt pulserande** när preflight är klar, **blått** vid START-verifiering och **fast rött** när BA-assistans kör mot samma verifierade RAPT-session.
- START kräver uttrycklig operatörsbekräftelse och server-side ny kontroll av profil-/session-/steg-ID, target och färsk BZ-telemetri (max 90 sekunder), inklusive huvudström och utgångsreadbacks.
- `sensor.brewassistant_brewday_start_status` samt `brewassistant.brewday_start_verified` tillkommer.
- Read-only fortsätter beräkna styrförslag men skriver inte till BZ; direkt avstängning av read-only får inte längre kringgå START-preflight.
- **ABORT högst i prioritet:** först OFF/0-begäran till värmare/pump och deras utilization, därefter RAPT-profilens STOP, sedan ny OFF/0-begäran. BZ-huvudström lämnas på för fortsatt återläsning. ABORT kan inte blockeras av ManualPlan-reset.
- Återaktivering efter ABORT kräver först read-only och startar **inte** bryggningen.
- RAPT Profile Runtime-korten (SV/EN) hittar korrekt RCL-profilsensor dynamiskt via `ba_source`, visar okänd temperatur som **—** i stället för falska `0,0 °C`, och varnar om källa/telemetri saknas.
- Återställda stale-varningar för RAPT Pill i fermentationskorten.
- Uppdaterade enhetstester, isolerat HA/RCL-smoke och dokumentation.

## Kända begränsningar

- START **startar ännu inte en inaktiv RAPT-profil från RAPT.io**. Knappen kan enbart aktivera BA:s assistans när samma RAPT BrewZilla-profil redan är verifierat aktiv.
- Manual Brewing och Brewfather Brew Tracker behöver egna START-handoffs innan knappen får bli grön för dessa källor. Se issue #258.
- **Mjukvaran kan inte garantera samma fysiska stopp som att dra ur sladden**. HA-tjänstekvittenser och avläst OFF/0 är inte bevis på fysisk avstängning. En oberoende brytare och fysisk uppsikt krävs under test.
- Read-only stoppar BA:s egna vanliga skrivningar, **inte** en externt körande RAPT-profil.
- Beta har inte genomgått fysisk nödstoppacceptans och får inte lämnas obevakad.

## Vattenprov — prioriterat

1. Kontrollera först lokalt att BZ är säker, alla enheter rapporterar färskt och BA är read-only.
2. Testa gul START med saknat/för gammalt källvärde: **ingen positiv BA-skrivning**.
3. Starta en RAPT-profil via RAPT/BZ och verifiera rätt session/steg. Grön START ska då visas först när samtliga krav är uppfyllda.
4. Tryck START och kontrollera identitetskvittens samt heat/pump enligt rätt source scope (RAPT äger target och heater).
5. Kontrollera profilens stegbyte, reconnect/fallback och ABORT under uppsikt.
6. ABORT ska försöka värmare AV, pump AV och heat/pump-utilization 0 %, **utan att bryta BZ huvudström**. Kontrollera fysisk effekt och readbacks. Start får inte kunna återupptas utan ny uttrycklig godkänd START.
7. Rapportera de faktiska loggarna och UI-graferna innan ny beta/stable.

## Publiceringskontroll — OBS befintlig felaktig release

En release med **tagg `2026.10.0b6` (utan inledande `v`) publicerades redan**, men dess Git-commit är exakt samma som `v2026.10.0b5` och manifestet där är `2026.10.0b5`.

**Den gamla felaktiga releasen och taggen måste därför raderas via GitHub UI före publicering av den riktiga 0b6.** Flytta inte om redan publicerad tagg i tysthet. Skapa sedan ny `v2026.10.0b6` med `beta`-mergens *nya commit SHA* som Target, markera Pre-release och kontrollera manifest/version i taggarkivet. `Set as latest stable` ska INTE användas.
