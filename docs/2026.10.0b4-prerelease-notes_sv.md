# BrewAssistant 2026-10 — fermentation provider + Brewfather stream beta (v2026.10.0b4)

**Releasenamn:** `2026.10.0b4`  
**GitHub-tagg:** `v2026.10.0b4`  
**Integrationsmanifest:** `2026.10.0b4`  
**Releasekanal:** Pre-release / HACS

## Syfte

2026.10.0b4 gör jäsutrustningen till ett explicit, persistent val i BrewAssistant
och kopplar samma normaliserade fermentation-runtime till antingen det
temperaturkontrollerade jässkåpet eller Grainfather GF30.

Jässtrategi och fysisk jäsutrustning är separata dimensioner:

```text
strategy
  -> recipe_schedule / framtida sg_control

provider
  -> fermentation_chamber / grainfather_gf30
```

Samma release lägger till provider-neutral telemetry för Brewfather Custom Stream.
BrewAssistant väljer och kvalitetssäkrar källorna; companion-integrationen
`Jocke1970/brewfather` äger HTTP-transporten.

## Ny provider-yta

Nya integration-owned entiteter:

```text
select.brewassistant_fermentation_provider
sensor.brewassistant_fermentation_provider
sensor.brewassistant_fermentation_provider_status
```

Stabila provider-ID:n:

```text
fermentation_chamber
grainfather_gf30
```

Befintliga lagrade sessioner utan provider migrerar till
`fermentation_chamber`. GF30 är explicit opt-in.

Ett explicit provider-val som görs innan en ny fermentation-session startas
bevaras när sessionen startas, så länge startpayloaden inte själv anger en
annan provider.

## Exklusiv control arbitration

Endast vald provider får vara control-eligible.

```text
fermentation_chamber selected
  -> chamber supervisor eligible
  -> GF30 proposal/write blocked

grainfather_gf30 selected
  -> GF30 supervised target eligible
  -> chamber proposal blocked
```

Providerbyte:

- rensar gammal provider-owned pending action;
- ändrar inte SG-/day-strategi;
- ändrar inte processmålet;
- återanvänder inte gammal confirmation;
- kräver ny provider-specifik Supervised Apply-proposal/confirmation.

GF30 kontrollerar provider både när proposal skapas och igen precis före
bekräftad extern write.

## Provider-aware dashboard

Nya gemensamma providerkort:

```text
dashboard/cards/fermentation_provider.yaml
dashboard/cards/fermentation_provider_sv.yaml
```

De befintliga provider-specifika korten är nu conditional:

```text
fermentation_chamber
  -> fermentation*.yaml visas

grainfather_gf30
  -> gf30_supervised_target*.yaml visas
```

Villkoren använder maskin-ID från
`sensor.brewassistant_fermentation_provider`, inte översatta select-labels.

## Brewfather Custom Stream — BA-export

Nya stabila provider-neutrala källor:

```text
sensor.brewassistant_brewfather_stream_status
sensor.brewassistant_brewfather_stream_temperature
sensor.brewassistant_brewfather_stream_gravity
sensor.brewassistant_brewfather_stream_temp_target
sensor.brewassistant_brewfather_stream_gravity_target
sensor.brewassistant_brewfather_stream_aux_temperature
```

Semantik:

```text
temp
  -> normaliserad öltemperatur

gravity
  -> normaliserad fermentation-SG

temp_target
  -> aktivt BrewAssistant-processmål

gravity_target
  -> target FG

aux_temp, chamber
  -> jässkåps-/chamber-luft

aux_temp, GF30
  -> coolant/reservoar
```

GF30:s interna öltemperatur exporteras inte som `aux_temp`, eftersom Brewfather
visar det fältet som **Fridge Temp**.

`ext_temp` lämnas omappat tills en riktig room/ambient-sensor finns.

## Freshness

BrewAssistant-exporten använder max 20 minuters sample-age för mätvärden.

- stale/missing primär öltemperatur -> exporten blir inte eligible;
- stale SG -> SG utelämnas;
- stale provider-specifik aux-temp -> aux-temp utelämnas;
- stabila target-värden får vara oförändrade längre än freshness-fönstret.

Ingen HTTP-post sker från BrewAssistant.

## Companion Brewfather-transport

Custom Stream-transporten ägs fortsatt av `Jocke1970/brewfather`.

Companion-`dev` är härdad med:

- HTTPS;
- minst 900 s mellan POST-försök;
- Fermenting/Conditioning batch-scope;
- samma 1200 s freshness-grind för mätningar;
- logging-ID maskeras från loggar/status;
- vanliga Brewfather API-credentials skickas inte till stream-endpointen;
- setup skapar ingen fake-reading;
- delivery diagnostics för sent/throttled/inactive/not-eligible/error.

BrewAssistant kan releasas oberoende eftersom exportentiteterna endast är
read-only sensors. För att använda hela Custom Stream-v1-kontraktet ska
companion Brewfather-integrationen också vara på den nya stream-koden.

## Säkerhetsgränser

Denna release ändrar inte grundägarskapet:

- `fermentation_tracking` äger processmålet;
- chamber-backenden adapterar endast när chamber är vald;
- GF30-backenden adapterar endast när GF30 är vald;
- GF30 äger sin heater och cooling-pump;
- coolant-`generic_thermostat` äger frysen;
- Brewfather Custom Stream är logging, aldrig en control-loop;
- den icke valda providern blir aldrig automatisk fallback-controller.

## HA-åtgärd

**Home Assistant-omstart krävs** efter HACS-uppdatering eftersom nya
integration-owned select-/sensor-entiteter tillkommer.

Efter omstart:

1. kontrollera att `select.brewassistant_fermentation_provider` finns;
2. kontrollera default `fermentation_chamber` på migrerad/inaktiv runtime;
3. växla provider och verifiera conditional UI;
4. kontrollera att icke vald backend visar control-ineligible;
5. konfigurera Brewfather Custom Stream mot de nya
   `sensor.brewassistant_brewfather_stream_*`-entiteterna om funktionen ska användas.
