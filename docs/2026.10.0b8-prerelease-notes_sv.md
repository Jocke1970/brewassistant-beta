# BrewAssistant 2026.10.0b8 – reconnect, Manual säkerhetsgränser och RAPT-profilruntime

**Kanal:** HACS Pre-release / endast övervakat vattenprov.
**Manifest:** `2026.10.0b8` · **tagg efter beta-merge:** `v2026.10.0b8`
**SOP:** dev → beta → main; main uppdateras inte.

## Ändringar sedan b7
- Prioriterad operatörspanel för återanslutning efter HA-omstart med synlig, backendguardad kvittens och fortsatt READ-ONLY. ABORT och verkligt fysiskt stopp är separata.
- Direktanrop till Manual-processens HA-tjänster blockerar mutationer vid kvarhållet RAPT/Brewfather-ägarskap, ABORT, fallback och resync.
- Runtime maskerar missvisande Manual-ägarskap, temperaturmål, timer och positiva skrivflaggor under resync. Ingen överlämning bara för att källan saknas.
- Kompakt READ-ONLY-panel, tydliga preflight-chip, ingen falsk 0-minuterstid. Manual-panelen döljs när den saknar giltig operatörsåtgärd.
- RAPT Profile Runtime visar stegnamn + nummer, separerar faktisk BZ-temperatur från RAPT-mål och BA-referens, varnar rött för ej verifierad data och jämför RCL:s steg-ID:n passivt.
- Källans färskhet använder explicit `profile_observed_at` från **RAPT Cloud Link 2026.10.0b4**. Temperatur/BLE age ensamt validerar aldrig profilkontraktet.

## Beroende
**Installera RCL b4 före BA b8.** Om RCL fortfarande är b3 saknas `profile_observed_at`; profilrutan visar därför avsiktligt overifierad, även när temperatur uppdateras. HA-backend och manuellt inklistrade Lovelace YAML-kort uppdateras separat.

## Releasegrind
1. Kandidat `2026.10.0b8` på dev med Python 3.11–3.13, kodkvalitet, HACS, Hassfest och isolerat HA/RCL-smoke på RCL b4 SHA.
2. Separat PR **dev → beta**, använd **Create a merge commit**, inte force push. Kör om CI på **exakt beta-merge-SHA**.
3. Skapa ny tagg `v2026.10.0b8` på beta-merge-SHA och GitHub **Pre-release**, aldrig Latest/stable.
4. RCL b4 HACS-uppdatering och HA-omstart före BA b8. Uppdatera hela YAML-filerna:
   - `dashboard/cards/brewday_control_status_sv.yaml`
   - `dashboard/cards/brewassistant_manual_brewday_sv.yaml`
   - `dashboard/cards/rapt_profile_runtime_sv.yaml`
5. Fälttesta med en aktiv RAPT-profil och bara vatten: oförändrat steg med ny profilobservation, riktigt stegbyte, RCL-bortfall, ABORT, read-only, identitetskvittens och separerad START.

**Säkerhet:** Enda normala styrvägen är BA → RCL → BrewZilla. Källbortfall är inte STOP; inga heater OFF, pump OFF, utilization 0 eller profilavslut enbart p.g.a. unavailable. Manuellt fysisk START (issue #258) är inte färdig. En HA-readback bevisar aldrig fysisk frånkoppling.
