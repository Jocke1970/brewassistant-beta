# BrewAssistant 2026-10 — GF30 profile-authority beta (v2026.10.0b2)

**Releasenamn:** `2026.10.0b2`  
**GitHub-tagg:** `v2026.10.0b2`  
**Integrationsmanifest:** `2026.10.0b2`  
**Releasekanal:** Pre-release / HACS

## Syfte

2026.10.0b2 hårdnar GF30:s supervised target-kedja så att endast den aktiva
jäsprofilens/receptschemats temperaturmål får bli ett GF30-setpointförslag.

BrewAssistants interna `tracking_rule` får fortsatt användas för observation och
fallback-logik i fermentation tracking, men är uttryckligen **inte** en auktoritativ
GF30-styrkälla.

## Auktoritativ targetkälla

Tillåten källa i denna release:

```text
brewfather_recipe_schedule
```

Flödet är:

```text
Brewfather fermentation profile / recipe schedule
  -> fermentation_tracking schedule interpretation
  -> GF30 profile target
  -> Prepare GF30 Target
  -> generic Supervised Apply
  -> explicit operator CONFIRM
  -> grainfather.set_controller_target_temperature(confirm=true)
  -> fresh MQTT readback
  -> verified
```

Om profilkälla saknas eller target endast kommer från `tracking_rule` blir läget
`waiting_for_profile` och ingen GF30 target-write kan förberedas eller utföras.

Executorn återvaliderar både targetvärde och profilkälla precis före write.

## Dashboard

Nya/uppdaterade kort:

- `dashboard/cards/gf30_supervised_target.yaml`
- `dashboard/cards/gf30_supervised_target_sv.yaml`

Kortet använder BrewAssistant-layouten och visar endast:

- Profilmål
- GF30 target
- avvikelse/synkstatus
- GF30 online/offline
- Apply Mode
- supervised apply-state
- Prepare / Reject / Confirm

Teknisk GF30-diagnostik hör fortsatt hemma i Grainfather/diagnostikytorna.

## Ny sensor

- `sensor.brewassistant_gf30_profile_target`

Den äldre `sensor.brewassistant_gf30_recommended_target` behålls för
bakåtkompatibilitet/diagnostik men används inte som GF30-kortets targetyta.

## Safety

- GF30 äger heater och cooling-pump lokalt.
- BrewAssistant får inte direktstyra heater/cooling.
- Target-write kräver profile-backed source + Supervised Apply + explicit CONFIRM.
- En ändrad profilkälla eller profiltemperatur mellan Prepare och Confirm stoppar write.
- En bekräftad åtgärd räknas inte som klar utan verifierad Grainfather MQTT-readback.
